## 7. 若上线：需要什么

### 7.1 不要复用 `session_links`

`session_links(session_id, linked_session_id, kind, created_at)` 是**人显式建立**的关系，
`MCP get_linked_sessions` 会把它当"显式关联"展示给用户，`rebuild.ts` 会跨库搬运，
`forget.ts` 会跟着删。往里塞自动边会：
① 让用户分不清"我挂的"和"机器猜的"；② 没有 `weight` 列，没法调阈值；③ 没有算法版本，没法重算/回滚。

### 7.2 新表（派生表，整表重建，仿 `graph_tag_*` 的做法）

```sql
-- 自动候选边：整表重建，不手工编辑，不参与检索打分
CREATE TABLE IF NOT EXISTS session_link_auto (
  session_id        TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  linked_session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  weight            REAL NOT NULL,   -- W
  signals           TEXT NOT NULL,   -- JSON: {topic,file,title,tag} 的分项 O_s
  evidence          TEXT NOT NULL,   -- JSON: 共享项（截断），给人看「为什么连上」
  kind              TEXT NOT NULL DEFAULT 'related',  -- related | dup（dup 不入图）
  algo_version      INTEGER NOT NULL,
  created_at        TEXT NOT NULL,
  PRIMARY KEY (session_id, linked_session_id)
);

-- 复用判据（仿 graph_meta：会话数 + 内容指纹，缺一个就会「图与库静默不一致」）
CREATE TABLE IF NOT EXISTS links_meta (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  version INTEGER NOT NULL,
  built_at TEXT NOT NULL,
  session_count INTEGER NOT NULL,
  edge_count INTEGER NOT NULL,
  fingerprint TEXT
);
```

**存储量**：18 376 条 × 约 200 字节 ≈ 3.7 MB（`evidence` 截断后）。若嫌大，
只存 `weight ≥ 0.30` 的 13 079 条 ≈ 2.6 MB；`weight` 可量化成 `INTEGER(×1000)` 省一半。

### 7.3 生命周期：新阶段 `links`，插在 `tags` **之后**、`aging` **之前**

现有 `STAGES` 顺序：`guard → repair → capture → extract → harvest → consolidate → compact → cleanup → tags → aging → distribute`。

新阶段：

```ts
{ id: 'links', title: '自动会话链接（派生边，不参与检索打分）', everySec: 86400, mutates: true, weight: 'heavy' }
```

位置理由：

- **必须在 `cleanup` 之后**：cleanup 会清洗 `topics` / `files_mentioned` 的噪声，
  在那之前建边等于拿脏输入算分。
- **放在 `tags` 之后**：同属「派生图」，一起重建省一次全表扫；且将来若要复用
  `graph_tag_sessions` 做标签侧信号，顺序必须在其后。
- **放在 `aging` 之前**：aging 会把老会话正文压成摘要（有损），
  而建边只读元数据不受影响——但**先建边**能保证 aging 之后图仍然新鲜。
- **`weight: 'heavy'`**：全对扫描 18 914 对 + 2 次全表读，实测**约 90–120 秒**
  （680 会话；n² 增长，2 000 会话会到 ~10 分钟）。按 `stages.ts` 的纪律
  「heavy = 只许跑在独立进程」，不能放进宿主 worker。
- **失败不阻塞**：与 `tags` 同款——图是增强，不是主链路；失败只告警。

### 7.4 用途（按证据排序）

| 用途 | 证据支持 | 说明 |
|---|---|---|
| ✅ **相关会话推荐的"重叠轨"升级** | 强 | `related.ts` 现有的 `overlapScore`（topics×3 + tags×2 + files + title，**无 idf、无归一、无 dup 护栏**）正是本脚本的朴素版；换成 idf+余弦后，样例 #1（同一本书 31-38 章 vs 33-40 章的连贯性核查）这类边才排得上来 |
| ✅ **MCP `suggest_related_sessions` 的兜底轨** | 中 | 向量轨需要 embedder；这条轨纯元数据，永远可用 |
| ⚠️ **C-expand 式召回扩展** | 弱（持平） | 只在「主路 0 命中」时试，且必须限 1 跳、限 top-3 种子 |
| ❌ **检索排序打分** | **反证** | A-count 显著变差（χ²=5.14, p<0.05）；A-prop 与基线完全相同 |
