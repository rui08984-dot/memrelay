## 2. 链接定义（零模型、零 embedding、零随机）

四个信号，全部取自**已有的派生列**（不需要新抽取、不需要跑模型）：

| 信号 | 来源 | α | 停用项阈值 |
|---|---|---|---|
| `topic` | `sessions.topics[]`（抽取器产出） | 3.0 | df/N > 0.10 |
| `file` | `sessions.files_mentioned[]` 的 **basename** | 1.5 | df/N > 0.10 |
| `title` | `sessions.title` 经 `tokenizer.segment` 分词（≥2 字） | 1.0 | df/N > 0.10 |
| `tag` | `sessions.user_tags[]`（**人打的**） | 1.0 | df/N > **0.03** |

信号内部做 **idf 加权 + 余弦式归一**：

```
df(x)  = 同 project 内含 x 的会话数
idf(x) = ln(1 + N/df(x))，且 df<2 ⇒ 0（只出现一次，无法共享）
O_s    = Σ_{共享非停用项} idf / sqrt(Σ_a idf · Σ_b idf)
W      = Σ_s α_s · O_s          ∈ (0, ~5]
```

**为什么必须做 idf + 归一**：不做的话，两个都提到「文件」「模型」「dsh」的会话就会被判为强相关。
实测 df：`文件` 130/680、`模型` 105、`dsh` 94、`llama.cpp` 69、`AGENTS.md` 64。
归一（除以两侧总量）进一步保证"共享一个高频词"不会因为会话本身很长而占便宜。

**tag 为什么单独收紧到 0.03**：14 个 tag 里 6 个 df≥34（`selftest` 67 / `review` 34 / `1021` 34 / `decision` 34 …），
它们描述的是「这批会话都来自同一次批处理」，不是「同一件事」。不收紧的话，一次批处理派出的
N 个 subagent 会话会互相连成完全图。

### 证据门槛

除 W>0 外，还要求：**至少 2 个不同的非停用共享项**，或**单个强项**（topic/file 的 idf≥4，即 df≤5）。
这条把「只共享一个 `输出`」这类边挡在外面（见第 8 节样例 #9、#10）。

### 重复/样板会话护栏（`kind='dup'`，不进扩展图）

标题归一后完全相同，或标题词元 Jaccard ≥ 0.85（两侧词元数 ≥3 才算）⇒ 判 dup。

**这条不是洁癖，是必需**：被剔除的 538 条 dup 边里，权重最高的三条是 5.50 / 5.41 / 5.32，
**全部高于 live 边的最高分 4.88**。也就是说，**不加护栏的话，全图最"可信"的边 100% 是重复执行**：
「Selection side chat」×2、「workflow subagent actor#4@1」×2、同一份 HANDOFF 提示词派了 2 次。
它们共享 5 个 tag + 完整标题 ⇒ 分数爆表，但那是「同一件事被跑了 N 遍」，不是「跨会话知识」。
